# Why the rules are the way they are

Arin's rules come from hands-on cleanups of developer Macs that run coding agents across many parallel worktrees. This file records what those cleanups showed, so rule changes can be checked against evidence.

## Where the space usually goes

| Source | Commonly seen | Notes |
|---|---:|---|
| Go build cache (`~/Library/Caches/go-build`) | 5–20+ GB | Can grow by tens of GB in a day when agents build and test many worktrees in parallel. Go only trims entries unused for ~5 days and has no size cap. |
| Per-run Go caches in `$TMPDIR` and `/tmp` | 3–18 GB | One-off `GOCACHE` folders that tools and agents create for a single build or lint run. |
| Xcode DerivedData, including copies in `$TMPDIR` | 2–25 GB | Scripted builds (perf or screenshot runs) often keep their own multi-GB copy. |
| Simulator device data | 5–25 GB | Includes devices left unavailable after runtime upgrades. |
| Duplicate or beta simulator runtimes | 8–18 GB each | A beta runtime next to the release build of the same version. |
| Git worktrees | 5–25 GB merged and clean | Hundreds of linked worktrees accumulate. Most of the size is repeated `bin/`, `.build`, and `node_modules`. |
| Repo-root `bin/` folders | Up to tens of GB | Envtest `bin/k8s` copied into every worktree, linters, controller-gen, Python test environments. |
| `node_modules` / Swift `.build` | 5–15 GB each | Repeated in every worktree. |
| Package caches | 10–20 GB | uv, pnpm, Homebrew, bun, npm, trivy, golangci-lint, SwiftPM, Yarn. |
| Old tool releases | 3–4 GB | Old Codex releases, old Claude Code and Copilot versions, unused Rust toolchains. |
| Agent data | 15–55 GB | Codex sessions and a second copy of them in its thread history database, a log database that is mostly free pages, review and validation folders, Claude's Cowork VM. |

## Rules that came from mistakes

1. **Measure free space, not folder sizes.** `du` counts APFS clones and shared blocks in full. Deleting 12 GB of session files has freed under 5 GB; removing unavailable simulators can free almost nothing; code-signing clones can report tens of GB that is mostly shared. Arin reports the measured change in free space and explains any gap. Estimates use each file's APFS private size (`ATTR_CMNEXT_PRIVATESIZE`), counting a clone family's shared blocks only when every clone is inside the item: a worktree's `node_modules` copied as clones from another worktree measured 257 MB in `du` and frees almost nothing. Snapshots and clones changed after copying still hold blocks, so the estimate stays an estimate.
2. **Snapshots hold deleted files.** A staged macOS update creates `com.apple.os.update-*` and `MSUPrepareUpdate` snapshots, and gains stop showing up. Never delete Preboot, `/System/Library/AssetsV2`, or update snapshots by hand. Finish the update and restart instead.
3. **Read-only trees break `rm`.** Go module caches and envtest binaries are read-only, which breaks worktree removal and deleting `bin/`, `.build`, and worktrunk trash. Arin's remover makes each folder the user owns writable just before emptying it, through the descriptor it checked; files keep their modes, since removing a file only needs its folder writable. A folder it can't open at all is left and reported, because a chmod by name can't be pinned to the folder that was checked.
4. **Native cleanup commands don't always work:**
   - `pnpm store prune` frees nothing while deleted projects are still registered.
   - `bun pm cache rm` refuses to run outside a project.

   Arin deletes those two stores directly. For Go, npm, uv, and Homebrew, the native commands work and are preferred. A native command cleans the tool's configured location, so Arin asks the tool where that is and validates that path, not a default.
5. **Check what's running right before acting.** Browsers and editors use their caches, ShipIt updates mid-cleanup, `gopls` and Go tests rebuild the cache while it's being removed, booted simulators use their data, and live agent sessions run old tool releases. Arin re-checks running processes, open files, and recent writes anywhere in the tree immediately before each item, not only at scan time.
6. **"Merged" needs squash detection.** Most PRs are squash-merged, so ancestry alone misses them. A worktree counts as merged when HEAD is in the default branch, or a merged PR's head equals HEAD or is ahead of it. A branch with commits after its merged PR is unmerged work, so removal is refused if HEAD has moved since the scan.
7. **Agent worktrees can be alive.** A removed T3 worktree was recreated a minute later by a live thread. Worktrees under `~/.t3/worktrees` start as Review, and any worktree with a process working inside it is blocked.
8. **`bin/` isn't always generated.** It can hold issue notes, scratch source, or a nested git checkout. Arin only considers git-ignored, untracked repo-root `bin/` folders, and marks them Review unless they hold only executables and tool trees with no checkout inside.
9. **`.build` isn't always SwiftPM output.** It can hold a downloaded framework or a review log. Arin requires a sibling `Package.swift` and SwiftPM markers.
10. **Docker's CLI can hang.** `docker system df` can block forever while Desktop is wedged. Every Docker call has a short timeout, `Docker.raw` is never touched directly, and unattached volumes start as Review because they can hold databases. Orphaned `buildx_buildkit_*_state` volumes for deleted builders are safe. Cleanup is pinned to the Docker context that was scanned.
11. **Simulator runtime deletion can leave a mounted image.** The space comes back only after a reboot.
12. **Be clear about what isn't officially supported.** Compacting the Codex log DB is generic SQLite maintenance, not a Codex procedure, and it must not run while Codex writes. For Codex sessions, `codex delete` is the supported route because it removes database and index entries too.
13. **Agent scratch folders can hold real work.** An idle `/tmp/claude-*` folder that was mostly DerivedData also held a git checkout. Temp folders with a repository anywhere inside are not cleaned. A repository is any `.git` entry, a bare clone (`HEAD` beside `objects/` and `refs/`), or a git directory with `commondir` or `gitdir`. SwiftPM's clones in `.build` and `SourcePackages` pass only when they have no changes, stash, linked worktrees, hidden index flags, or commits (from HEAD, a branch, or a tag of their own) that their local mirror lacks; the mirror itself must be bare with no stash or worktrees; `pkg/mod` and `node_modules` aren't searched, since their tools own what's inside. A search that times out or hits an unreadable folder counts as finding one. Only layouts a tool rebuilds (a Go build cache, Xcode DerivedData, a `CACHEDIR.TAG` folder) start as Safe; an idle folder Arin doesn't recognize starts as Review.
14. **A fixed list of locations misses the biggest surprises.** Tens of GB of agent perf artifacts can sit in `~/.t3/userdata/task-artifacts`, outside every known cache path. A size overview of the home folder finds such folders and drills into the subfolder that actually holds the space. It never reports a folder containing a git checkout.
15. **It grows back.** A disk freed by tens of GB can be full again within days, mostly from Go cache, DerivedData, and agent perf artifacts. That's why Arin has low-space alerts and an opt-in Auto mode limited to caches that refill on their own. An alert re-arms only once free space is back above the threshold by 10% (at least 2 GB), so a disk hovering at the line doesn't alert on every dip.

## Rules not yet confirmed by a cleanup

These follow from documented tool behavior or from the rules above, not from a cleanup that went wrong. Confirm or revise each one the first time a real cleanup exercises it.

- **Active projects aren't pre-selected.** Deleting the build output of a project in use forces a reinstall or full rebuild in the middle of work, and the open-file check only catches what runs at that moment. Build output in a project whose files or git state (index, HEAD, reflog, following a linked worktree's `.git` file) changed within 7 days is listed but not pre-selected.
- **The keep list fails closed.** If it exists but can't be read (including a folder that can't be searched), nothing is pre-selected and the executor refuses every item. Running without the user's protections is worse than not running. It's re-read before each item, and it records each kept item's paths, so removing a worktree can't take a kept `node_modules` with it. The app and the CLI update it under a shared lock.
- **`CACHEDIR.TAG` marks a cache.** A folder holding the standard tag with the exact signature is meant to be deletable (pytest, mypy, ruff and others write one). Arin only accepts cache-named or hidden folders, never a project root, and never one with a checkout inside.
- **Build folders need their marker.** `.next` needs `package.json` and a `next.config.*`; Gradle `build` needs a Gradle script and Gradle's `build/tmp`; `.dart_tool` needs `pubspec.yaml`; Zig caches need `build.zig`. `.terraform` starts as Review: `terraform init` restores providers and modules, but `.terraform/environment` holds the selected workspace and init may need credentials.
- **Tool managers decide what's unused.** `mise prune --tools --yes <tool>` re-evaluates at cleanup time and keeps versions a running process uses; Arin only names the tool. Ollama models go through `ollama rm`, because layers are shared between models and deleting blobs directly would leave broken manifests; `ollama ps` is checked again right before, and a model that's loaded (or a check that fails) is skipped. LM Studio model folders are deleted directly, and only while LM Studio isn't running.
- **Time Machine local snapshots are not update snapshots.** Only names of the form `com.apple.TimeMachine.<date>.local` are offered, deleted one at a time with `tmutil deletelocalsnapshots <date>`. Rule 2 still stands for update snapshots. Their size can't be measured beforehand, so the measured change in free space is the only number reported.
- **Some tools get one exact command shape.** `tmutil`, `ollama` and `mise` can do far more than clean (turn off backups, delete every model, uninstall runtimes in use), so the guardrails accept only `tmutil deletelocalsnapshots <date>`, `ollama rm <name>`, and `mise prune --tools --yes <tool>`.
- **Uninstalling is its own step, for one app at a time.** App bundles never show up in a scan, a cleanup level or Auto mode. The user picks an app; Arin lists the bundle and the items directly inside the per-app folders of `~/Library` (Application Support, Caches, Containers, Group Containers, Preferences, Saved Application State, HTTPStorages, WebKit, Cookies, LaunchAgents, Logs, crash reports) whose name is the app's bundle ID or starts with it plus a dot. Folders named after the app instead of its bundle ID, and group containers, are listed unchecked: a name can be shared, and group containers serve every app from the same developer. Files of another installed app (`com.foo.app.pro` for `com.foo.app`) and of a second copy of the same app are left alone or unchecked. Apple's apps and Arin aren't offered. Everything goes to the Trash, so History can put it back, except a Homebrew cask's bundle, which goes through `brew uninstall --cask <token>` so Homebrew doesn't keep a stale install. Nothing is removed while the app runs, kept paths are refused, and if the bundle can't be removed, its files stay too. Uninstalls have their own guardrail (`checkUninstall`): cleanups still can't reach `/Applications`, Preferences or Group Containers, and uninstalls can't reach the rest of the protected list.
- **A clean `git status` doesn't make a worktree safe to remove.** Reproduced in a sandbox with git 2.56.1: `git worktree remove` without `--force` deleted an ignored folder holding a clone with an unpushed commit, and deleted edits to a tracked file marked assume-unchanged; `git status --porcelain` was empty both times. Arin refuses such worktrees: it searches each ignored folder (`git ls-files --others --ignored --directory`) for repositories, and checks `git ls-files -v` for assume-unchanged and skip-worktree files that are on disk. It checks at scan time and again right before `git worktree remove`.
- **Build output must be git's to throw away.** A name and a marker file say what a folder is, not that it holds nothing else: `pip install -e git+…` clones into `<venv>/src`, an edited SwiftPM checkout lives in `.build/checkouts`, and JavaScript GitHub Actions commit `node_modules`. Project build output is cleaned only when git ignores it, tracks nothing in it, and no repository inside holds work (same check as rule 13). It runs at scan time and again right before deleting. Folders outside any repository have nothing for git to protect and skip the first two checks; a `.git` entry above that git can't read counts as a repository.
- **No open-file check, no cleanup.** When `lsof` returns nothing, nothing shows whether an app or a build is using a folder, so the executor skips every item that has paths, the same way it treats an unreadable keep list.
- **mise can ignore a config it can't load.** mise logs `error loading tracked config file <path>: <error>` and drops that config (`src/config/mod.rs`, mise 2026.10.14), so a version only it pins counts as unused. Arin runs `mise prune --tools --dry-run` with info logging at scan time and before each prune, and refuses while a config that may still exist fails to load.
- **Bun's global store is not cache.** Bun 1.4.4 documents that `bun pm cache rm` also deletes the global store in `links/`, which projects with `globalStore = true` link into, and that `bun pm cache prune` keeps it. Arin deletes the cache's entries directly (rule 4), never the folder itself, so a `links/` made after the scan stays too.
- **DerivedData can outlive its project.** Xcode records the workspace in each DerivedData folder's `info.plist` (`WorkspacePath`). When that path no longer exists (often a removed worktree), the folder is offered as orphaned. A path on a volume that isn't mounted, or one that can't be read, doesn't count. A DerivedData folder whose `SourcePackages` holds an edited checkout or another repository is kept (rule 13's check), whatever its project's state.
- **Agent sessions are activity.** A Claude Code session that only reads files or runs tests leaves no trace a file-time check sees, but it writes its transcript under `~/.claude/projects/<working directory with every non-alphanumeric character as ->`. Transcripts in the project's repository or below it count toward the 7-day activity window.
- **Hooks can point git elsewhere.** `GIT_DIR`, `GIT_WORK_TREE` and similar variables, set by a git hook that runs `arin`, make `git -C <dir> status` inspect another repository (reproduced in a sandbox). Arin removes them from every command it runs.
- **Deletes stop at a volume boundary.** Reproduced in a sandbox: with a disk image mounted inside a folder, `rm -rf` on the folder deleted the files on the image before failing with `Resource busy`. The guardrails refuse any path that is a mount point or has one below it (an attached image, a network share, a FUSE mount), and fail closed if mounts can't be listed. The remover itself never descends into another volume, so a mount that appears after the check is left alone too.
- **Report what a delete left behind, and why.** `FileManager.removeItem` stops at the first failure and reported a busy mount point as "you don't have permission". Arin removes entry by entry without following symlinks, carries on past what it can't remove, empties a folder again if a running app refills it mid-delete, and reports a partial result naming the cause: a Finder lock (`uchg`), a file owned by another user, System Integrity Protection, a busy folder and what holds it, or missing Full Disk Access.
- **IDs must all match.** `arin clean --ids` and `arin plan --ids` do nothing when any ID matches no candidate (or, with `--plan`, isn't in the plan or is refused by the fresh scan), and a value flag given twice is an error, so a typo or a repeated `--ids` never cleans a different set than the one reviewed.
- **Missing developer tools aren't tools.** Without Xcode or the Command Line Tools, `/usr/bin/git`, `xcrun` and similar are stubs that open macOS's install dialog. Arin treats them as not installed unless a developer folder exists.
- **Agent history goes through the agent's own delete command.** Codex keeps each session in a rollout file, a row in its state database, rows in its paginated thread history and an entry in its name index. Reproduced in a sandbox `CODEX_HOME` with Codex 0.170: `codex delete --force <uuid>` removed the `.jsonl` and `.jsonl.zst` rollouts and their rows. Its source shows it also takes the session's writer lock, removes the subagent threads the session spawned, and refuses a session with an attached thread. Arin offers sessions whose whole tree has been idle 30 days (Claude Code's default retention) and isn't pinned, reads the tree again right before each delete, skips one used since the scan, and carries on with the rest. Each delete runs with `CODEX_HOME` set to the folder that was scanned. A deleted session can't be resumed, so they start as Review at the Deep level.
- **Codex keeps a second copy.** `thread_history_1.sqlite` held 5.5 GB, none of it free pages, next to 6.4 GB of session files. Deleting sessions frees pages inside it, not on disk, so it joins the log database under rule 12's compact-while-Codex-is-quit item.
- **A project folder's name isn't its path.** Claude Code names `~/.claude/projects/<folder>` by replacing every character but an ASCII letter or digit with `-`, so `/x/.t3/a_b` becomes `-x--t3-a-b`, and `/x/-t3/a-b` gets the same name: no decoding gets the path back. Arin reads the `cwd` the folder's newest transcripts record and uses one only if it encodes to the folder's name. On one Mac 5 of 131 folders recorded a directory that didn't (sessions in a worktree inside the repository), and those are left alone.
- **Gone means "no such file".** A working directory counts as gone only when `lstat` says ENOENT, its nearest existing parent is a folder Arin can search, and it isn't on a `/Volumes` disk that's not mounted. When nearly every project looks gone (90% of at least 5), the home was probably copied from another Mac or a disk isn't attached, so nothing is offered. A folder that's back by cleanup time, such as a recreated worktree (rule 7), is skipped, and so is one whose transcripts were written in the last day.
- **`claude purge` cleans what deleting the folder would miss.** Reproduced in a sandbox home with Claude Code 2.1.327: `claude purge --yes <dir>` for a missing directory removed its project folder and its entry in `~/.claude.json`, kept the other projects, and backed up `~/.claude.json` first. It also deletes the project's auto memory, so projects with notes in `memory/` start as Review. Many sessions write `~/.claude.json` at once, so editing it is left to Claude Code's own command.
- **Arin never edits agent history in place.** It doesn't cut tool output out of transcripts or delete database rows. The tools' own commands keep their indexes in step, and a transcript changed underneath a tool may no longer resume. Arin removes whole sessions with those commands and compacts databases only while the tool is quit.
- **Some cleanup only runs inside the tool.** Copilot CLI's `/session prune --older-than <days>` keeps its search index in step and skips sessions open in other windows, but it's an interactive command. Arin reports the size of `~/.copilot/session-state` and the command instead of deleting folders, and the size overview skips that folder and `~/.codex/archived_sessions` for the same reason.
- **Retention settings have gaps.** Claude Code deletes transcripts older than `cleanupPeriodDays` (30 by default), except those of sessions started or continued in Claude's desktop app, which it keeps at any age unless `desktopSessionCleanupPeriodDays` is set. Arin points that out once old transcripts add up.
- **Downloads an app replaces.** Copilot CLI keeps the updates it downloaded in `~/.copilot/pkg/<platform>`. The newest stays, since the CLI may launch it instead of the version it shipped with, and so does any a process runs from. Unfinished downloads in `pkg/tmp` go after an hour idle. A staged GitHub Copilot app update and Claude's Cowork VM (`vm_bundles`, 12 GB) should be downloaded again by their apps, but that hasn't been observed, so both start as Review and need their app quit.
- **Saved plans don't outlive their facts.** A plan stores each item's action; running it rescans and refuses items whose action changed, which catches a worktree with a new commit or a new snapshot.

## Things that stay hands-off

- Messages, Mail, Photos, iCloud Drive, Documents, Desktop, and Downloads. Point people to System Settings → Storage instead.
- The CoreSpotlight index, Keychains, `~/.ssh`, and cloud credentials.
- Application bundles, outside an uninstall the user starts for that app.
