# 0007: Remove agent history only through each agent's own command

**Status:** Accepted

## Context

Coding agents keep each conversation in several places. Codex keeps a rollout file (compressed in place once idle), a row in its state database, rows in its thread history database, and an entry in its name index. Claude Code keeps one folder per working directory under `~/.claude/projects`, holding transcripts and the project's `memory/`, plus an entry in `~/.claude.json`. Deleting files or rows directly leaves sessions listed that can't be opened, or a transcript that can no longer be resumed. Agent history is also the user's record of past work, so a mistaken cleanup costs more than a cache would.

## Decision

- Remove Codex sessions only with `codex delete --force <uuid>`, and Claude Code project data only with `claude purge --yes <dir>`. Each tool removes its own index entries together with the files. Guardrails allow exactly those shapes: one UUID, or one absolute, normalized path at least two levels deep with no `..` or control characters. Never `--all`, an option, or a relative path. Never rewrite transcripts or delete database rows directly. Copilot CLI's session pruning only runs inside Copilot, so Arin reports it instead of acting.
- Offer a Codex session tree, a root and the subagent threads it spawned, only when the newest activity anywhere in it is at least 30 days old, it isn't pinned or attached to another thread (Codex refuses those), its rollout files sit inside Codex's own session folders, and none of its files are open. A subagent whose parent row is missing is never a root, so it's never offered. Read the newest `state_<n>.sqlite`, the database the installed Codex uses, read-only, waiting up to five seconds when it's locked. When Codex is installed and has that database but its version can't be checked, is too old, or the database can't be read, report it with the scan's rule errors rather than listing nothing. Pin `CODEX_HOME` to the scanned home when running the command, and `HOME` for `claude purge`, so neither acts on a different home than the one scanned.
- Let the user raise the age, with `--older-than DAYS` or a setting, from 30 days to 10 years. It applies to Codex sessions and to Claude Code data for deleted folders, which otherwise need one day without writes. The check before each command keeps the default ages: it guards against use since the scan, and the age choice was already applied when the list was built.
- Derive a Claude Code project's directory from the first `cwd` each of its transcripts records, never from the folder name. Read every transcript up to that record; when one can't be read, or the record isn't found within 32 MB, the folder counts as unknown. The name replaces every UTF-16 code unit other than an ASCII letter or digit with `-`, so it can't be decoded back (`/a/b-c` and `/a/b/c` share one). Count a recorded path only when it encodes to the folder's name, and treat the folder as gone only when every such path is gone. Skip the rule when `CLAUDE_CONFIG_DIR` points elsewhere, since `claude purge` would act on another folder.
- Treat a directory as gone only on "no such file", only when its nearest existing parent is a directory Arin can search, and only when it isn't on a volume under `/Volumes` that isn't mounted. Anything else is unknown. When at least 90% of at least five projects look gone, as on a home copied from another Mac or with its disk detached, offer nothing.
- Start a project with notes in `memory/` as Review, since `claude purge` deletes them. Skip a project with any write anywhere inside it within the last day, checked recursively and treated as recent when the check fails; a session may still be running in the deleted folder.
- Every path a command will remove is read again right before it runs, and must pass the guardrails, be one of the paths the scan listed for review, and not be reached through a symlink: a rollout file or its folder must resolve inside Codex's own session folders, and a Claude Code project folder must not resolve anywhere else.
- Copy what each command will remove to the Trash right before running it: a Claude Code project folder as one item that Put Back can restore, and a Codex session's rollout files in one folder per session. When the copy fails, skip that item. The space is freed once the Trash is emptied, and the result says so.
- Check that the installed command still does what was tested, instead of pinning versions. Before each `claude purge`, its `--dry-run` must list exactly the project's folder once, its `~/.claude.json` entry once when that file has one (and none when it doesn't), and nothing else. After the copy to the Trash, run every check again; if anything changed while copying, skip the item and leave the copy in the Trash. Codex has no dry run: require Codex 0.170 or later, where `codex delete` was checked, and after each delete confirm the session is gone and that every thread outside its tree is still there, comparing thread IDs rather than counts so a thread created meanwhile can't hide one that was lost. If another thread went, or the database can't be read afterwards, count that delete as failed and stop the run, so an unexpected result affects one delete, not the rest. Run this check after every command, including one that exited with an error. Count an item as removed only when everything it covers is gone: every thread in a Codex session's tree and all its rollout files, or a Claude Code project's folder and its `~/.claude.json` entry.
- Don't wait for Claude Code to quit before purging: Claude Code locks and re-reads `~/.claude.json` when it writes it, and concurrent purges kept every unrelated entry.
- One candidate covers many sessions or projects, and each command is checked again right before it runs: the tree or folder is read again, and every recorded path that shares the folder must still be gone, so a session resumed, a subagent spawned, or a folder recreated since the scan is skipped. Open-file state is refreshed when it's more than a few seconds old, and an item is skipped when it can't be read. A refused or failed item doesn't stop the rest, and a partial result credits only what's gone afterwards.
- Keep the newest Copilot CLI package per platform, since the CLI may launch it in place of the version it shipped with, and any version a running process uses.
- Keep the home size overview out of agent history folders that have their own deletion commands, so they're never offered as plain folders to delete.

## Consequences

Sessions can stay on disk longer than strictly needed, and a host where most projects look gone gets no Claude Code cleanup at all. Freeing space inside Codex's thread history database still needs a compaction with Codex quit. Rules follow the agents' current storage layouts and need rechecking when an agent changes them. See [cleanup learnings](../learnings.md) for the observed behavior behind these rules.
